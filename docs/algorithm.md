# Как устроен обход

## Общая схема

```
start_urls + sitemap
        │  (нормализация, фильтры)
        ▼
  CrawlerQueue  ◄───────────── новые ссылки (глубина + 1, если не глубже max_depth)
        │ get_next()
        ▼
  N рабочих задач (workers, N = max_concurrent)
        │
        ├─ robots.txt: можно ли? ── нет ──► mark_skipped
        ├─ RateLimiter.acquire(домен)      (ждём своего слота по скорости)
        ├─ SemaphoreManager.limit(домен)   (лимиты: всего и на домен)
        ├─ HTTP GET (aiohttp, пул соединений, таймаут растёт при повторах)
        │      └─ ошибка ──► классификация ──► RetryStrategy / CircuitBreaker
        ├─ HTMLParser (поток или процесс) ──► страница + ссылки
        ├─ Storage.save()                  (буфер / батч, ошибки записи не останавливают обход)
        └─ ссылки в очередь, mark_processed
```

## Очередь

`CrawlerQueue` хранит адреса в куче: больше `priority` значит раньше, при равенстве по порядку добавления. Для обхода в ширину приоритет ссылки равен `-(глубина)`, то есть страницы ближе к началу идут первыми.

Один адрес принимается один раз (`seen`), лимит `max_urls = max_pages` ограничивает число принятых адресов, поэтому обработанных страниц не больше `max_pages`.

`get_next()` не возвращает `None`, пока какая-то задача ещё работает: она может добавить новые ссылки. Он ждёт события и возвращает `None` только когда очередь пуста и ничего не в работе. Поэтому ссылки добавляются в очередь до вызова `mark_processed`.

## Нормализация адресов

`normalize_url` делает ссылку абсолютной (учитывая `<base>`), убирает якорь `#...`, приводит схему и домен к нижнему регистру, пропускает только `http` и `https` (`mailto:`, `javascript:` отбрасываются). Благодаря этому `/page/1`, `/page/1#x` и `HTTP://Host/page/1` считаются одним адресом.

## Вежливость

1. `robots.txt` загружается один раз на сайт (защита от одновременных загрузок) и кэшируется. Нет файла, ошибка сервера, таймаут: считаем, что можно всё, и пишем предупреждение.
2. `Crawl-delay` (в том числе дробный) становится минимальной паузой для домена.
3. `RateLimiter` выдаёт слоты запросов: `слот = max(сейчас, предыдущий слот + пауза)`. Пауза = максимум из `1/rps`, `min_delay`, `Crawl-delay`, плюс случайная добавка `jitter`.
4. После ошибки сервера, `429`, таймаута или обрыва пауза удваивается (до `max_backoff`), после успеха сбрасывается.

## Ошибки и повторы

| Ошибка | Тип | Повтор |
|---|---|---|
| таймаут, 5xx, 429 | `TransientError` | да |
| отказ соединения, DNS, обрыв | `NetworkError` | да |
| 404, 403, 401 и другие 4xx | `PermanentError` | нет |
| запрещено `robots.txt` | `RobotsBlockedError` | нет |
| домен заблокирован автоматом защиты | `CircuitOpenError` | нет |

Пауза перед n-м повтором: `base_delay * backoff_factor ** n`, не больше `max_delay`; на `429` дольше, с учётом `Retry-After`. Таймауты при повторах растут. Незнакомые исключения (например, баг в коде) не глотаются.

`CircuitBreaker` для домена: `closed` → `open` (много сбоев за окно) → `half-open` (через `recovery_time` одна пробная попытка) → `closed` при успехе или снова `open` при неудаче.

## Конкурентность

Один процесс, один event loop, много корутин: пока одна ждёт ответ, работают остальные. Лимит одновременных запросов обеспечивают семафоры (`max_concurrent`, `max_per_domain`), скорость по времени обеспечивает `RateLimiter`. Блокирующую работу выносим из event loop: разбор HTML в поток или процесс, запись файлов через `aiofiles`, SQLite через `aiosqlite`.

## Сохранение

Каждая обработанная страница превращается в запись стандартного формата и уходит в хранилище. Хранилища буферизуют записи (файлы) или собирают пакеты (SQLite) и сбрасывают на диск порциями; при ошибке записи делается несколько повторов, потом ошибка учитывается в `storage_errors`, а обход продолжается.

## Остановка

Отмена (`CancelledError`, Ctrl+C) останавливает все рабочие задачи, закрывает сессию и хранилище, буфер записей сбрасывается при закрытии.
